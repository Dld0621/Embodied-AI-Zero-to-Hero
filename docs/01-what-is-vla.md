# VLA 核心概念：从一张图到下一步动作

**更新：2026-11-15。** 从具体任务建立直觉，再进入[第 09 课：完整 VLA 系统](learning-core/09-vla-systems.md)、[双语专项](specializations/vla-zero-to-one-cn.md)与[研究导读](30-vla-research-guide.md)。具体模型的输入、动作头和开放状态按原论文区分。

## 1. 先看一个杯子任务

桌上有红杯和蓝杯，你说“把红杯放进左边托盘”。机器人这一刻能得到相机图像、关节位置以及指令。策略必须给出接下来能交给控制器的数字，再根据新观测纠正动作。

```text
图像：红杯、蓝杯、托盘     指令：移动红杯     状态：关节与夹爪读数
                 ↓ 按 checkpoint 的预处理合同编码
              条件策略：预测一个动作或一段动作
                 ↓ 反归一化、坐标/动作转换、执行检查
              控制器执行有界前缀 → 重新观测
```

VLA（Vision-Language-Action）是以视觉和语言等信息为条件、生成机器人动作的策略模型。语言可以指定目标，视觉提供场景，本体状态提供机器人自身情况；哪些输入实际使用，要查模型。触觉、历史图像、深度或力信号属于可选扩展。

VLM 可以回答“杯子在左边”，VLA 还需要把任务落到动作表示和控制时序。动作输出仍需控制器执行，语义理解本身不保证运动可行。

## 2. 每一种输入提供什么？

| 信息 | 杯子任务中的作用 | 缺失或错误会怎样？ |
|---|---|---|
| 图像 | 区分颜色、位置和运动阶段 | 遮挡、相机变化可能使策略失败 |
| 语言 | 在同一场景下选择红杯和左托盘 | 只用固定指令训练，可能忽略文字 |
| 本体状态 | 说明手臂和夹爪当前构型 | 图像相似不代表关节状态相同 |
| 历史 | 推断运动方向或遮挡前状态 | 单帧可能无法确定速度和接触阶段 |
| 触觉/力 | 识别滑移、接触和载荷 | 是否存在、部署是否可用需单独检查 |

时间也属于输入合同。用未来相机帧解释当前示教动作会泄漏答案；用过期图像控制会增加观测年龄。统一相机名不能解决曝光、时间戳、坐标和标定问题。

## 3. 不要把所有模型画成同一个结构

常见组件包括视觉表征、多模态主干、动作生成模块。它们可以共享 token 流，也可以由语义主干与独立 action expert 交互。

| 代表路线 | 具体实例 | 应查什么？ |
|---|---|---|
| VLM 输出离散动作 token | RT-2、原始 OpenVLA | token 如何映射为每个动作通道 |
| 连续并行动作块 | OpenVLA-OFT | 动作头、L1 目标、预测长度与执行前缀 |
| 通用扩散策略 | Octo | 语言/目标图像条件、模块化输入输出 |
| VLM + 流匹配 action expert | π0、SmolVLA | 状态输入、向量场目标、积分步数 |

原始 [OpenVLA](https://arxiv.org/abs/2406.09246) 组合 DINOv2、SigLIP 视觉特征与 Llama 2 语言主干；不能把 SigLIP 标成语言编码器。[Octo](https://arxiv.org/abs/2405.12213) 是通用策略的重要比较对象，但不能据此认定所有语言条件策略都使用大型预训练 VLM。

## 4. 动作是数字，但数字还没有物理含义

一个教学 checkpoint 可以输出 `[0.01, 0, 0, 0, 0, 0, 1]`。补齐以下合同，才能解释它：

| 字段 | 教学示例 | 容易误读的地方 |
|---|---|---|
| 位置通道 | 基座坐标系末端增量，单位 m | 0.01 m 是 10 mm；不是 0.01 rad |
| 旋转通道 | 旋转向量，单位 rad | 旋转向量不能当欧拉角相加 |
| 夹爪通道 | 绝对开度，0 闭合、1 张开 | 其他数据可能采用相反极性 |
| 归一化 | 随训练保存的统计和 mask | 归一化 0.5 不等于 0.5 m |
| 时间 | 20 Hz 的一个采样间隔 | 不能在 500 Hz 伺服中重复累加同一增量 |

这只是示例合同。模型名、RLDS/LeRobot 格式和向量维数都不能替代这些字段。关节目标需匹配关节顺序与限位；末端动作需匹配坐标系、IK/控制器和可达性。详见[动作表示](24-action-representation-and-tokenization.md)。

## 5. 四种动作生成方法，分别在学什么？

| 方法 | 训练目标直觉 | 推理过程 | 主要代价 |
|---|---|---|---|
| 确定性连续回归 | 让预测接近示教 | 一次输出单步或动作块 | 单一输出无法完整表达多种可行动作 |
| 自回归 token | 预测下一个动作编码 | 顺序生成编码再解码 | 量化/编码误差和串行开销 |
| 扩散 | 从带噪动作恢复目标分布 | 多步采样生成动作块 | 采样器、步数与网络成本 |
| 流匹配 | 学噪声到动作的运输向量场 | 沿向量场积分生成动作块 | 积分误差、步数与网络成本 |

MSE 的最优确定性输出对应条件均值，逐分量 L1 对应条件中位数；不要都叫“取平均”。ACT 含 CVAE 训练结构，也不能直接归入普通 MLP 回归。流匹配不因使用 ODE 就必然比所有扩散采样器快；必须匹配网络、采样步数、硬件与动作质量比较。参见[生成式策略课](learning-core/06-generative-policies.md)、[OFT](https://arxiv.org/abs/2502.19645)、[π0](https://arxiv.org/abs/2410.24164)和[SmolVLA](https://arxiv.org/abs/2506.01844)。

## 6. 三种时间尺度，亲手算一次

动作采样为 20 Hz，每步 50 ms；预测长度 H=16，但只执行 K=4。假设观测后串行推理耗时 100 ms，执行期间不重新推理：

$$
\begin{aligned}
T_{\mathrm{cycle}} &= 0.1+4/20,\\
&=0.3\ \mathrm{s},\\
f_{\mathrm{replan}} &\approx3.33\ \mathrm{Hz},\\
f_{\mathrm{cmd}} &\approx13.33\ \mathrm{Hz}.
\end{aligned}
$$

16 步描述标称 0.8 s 采样时域，不表示全部执行；20 Hz 是块内动作间隔，不是含推理等待后的平均命令频率；低层关节伺服可以采用另一频率。在以上时间定义中，第 4 条命令开始于观测后 250 ms。增大 K 会减少推理等待占比，也会让后续动作依赖更旧的观测。

[打开第七个交互：VLA 动作合同与时序](learning-lab-cn.md#vla)，改变 K、推理耗时和归一化数值，先预测结果再核对。异步推理、时间集成和 RTC 是不同调度/生成方法，不能用串行公式代替实测。

## 7. 从监督学习到可评估策略

1. **定义任务和成功判据。** “抓到红杯”与“放稳后释放”分开记录；保留失败和干预。
2. **采集与划分。** 以 episode 为最小隔离单位；测试物体或场景泛化时还需按实体隔离。统计量只从训练数据拟合。
3. **跑通最小基线。** 先检查动作往返、数据对齐和 tiny-set overfit，再选择 ACT、连续动作块或 VLA 微调。
4. **按版本微调。** 冻结哪些层、LoRA 加在哪些模块、实际可训练参数有多少，都要从配置和日志确认。
5. **离线诊断。** 看每通道误差、padding mask、归一化、梯度与验证曲线；低 loss 不证明闭环成功。
6. **闭环评估。** 固定预算、初态和试验数；比较正确/交换/空指令、视觉扰动、状态遮蔽和延迟条件。

这条路线贯通[数据指南](21-vla-dataset-organization.md)、[微调手册](28-smolvla-gpu-finetuning-runbook.md)和[部署评测](20-vla-deployment-guide.md)。VLA 与显式感知、规划、IK 和反馈控制可以组合；VLA 不会自动获得跨机器人泛化。
