# 动作表示与 Tokenization：先解释数字，再选择生成器

**更新：2026-11-15。** 配套[动作知识点图解](knowledge-atlas/learning-action-representations/index.md)、[VLA 交互](learning-lab-cn.md#vla)和[完整 VLA 课](learning-core/09-vla-systems.md)。

## 1. 分清三个独立问题

- **物理语义：**关节角、末端位姿、速度或力矩？绝对目标还是增量？
- **统计变换：**如何用训练统计归一化、裁剪、处理无效维度并逆变换？
- **生成方法：**连续回归、离散 token、扩散或流匹配？

连续输出可以表示关节角，也可以表示末端增量；离散 token 最终也要还原成有单位的连续量。不能从“flow 模型”推断它输出哪种动作。

## 2. 本仓库的六类动作标签

见[真实动作容器](../examples/robot_foundation_models/common/action_schema.py)。以下只是解释示例，每个 checkpoint 仍需提供完整合同。

| action_type | 物理量 | 必须额外声明 |
|---|---|---|
| `joint_position` | 绝对关节位置 | 关节顺序、rad/其他单位、零位、限位 |
| `joint_velocity` | 关节速度 | rad/s、实际 dt、积分与停止行为 |
| `ee_pose` | 末端绝对位姿 | 参考系、四元数顺序、工具坐标和 IK |
| `ee_delta` | 末端位姿增量 | 基座/工具参考系、旋转表示、左乘/右乘约定 |
| `ee_delta_2d` | 平面末端增量 | 本地 PushCube 的缩放、轴向与任务平面 |
| `joint_delta` | 关节位置增量 | 相对实测还是先前目标、应用频率与限位 |

夹爪可能是独立的绝对开度、二元开闭或增量；必须单独定义。绝对命令避免了某些增量积分问题，但不保证没有跟踪误差或对初态鲁棒。增量在变换坐标系后也要旋转，不能说“不依赖坐标系”。

**重要合同：**[vanilla OpenVLA](https://arxiv.org/abs/2406.09246) 的末端控制输出不能直接贴上绝对关节角标签。本仓库适配器仍有[开放审查项 F002](reviews/content-correctness-audit.md)。[SmolVLA 基础配置](https://huggingface.co/lerobot/smolvla_base/blob/main/config.json)也不能替代本地任务的动作定义。

## 3. 归一化：0.5 究竟是多少？

用一个标量示例：训练物理范围是 ±20 mm，映射到归一化区间 [-1,1]。归一化值 u=0.5 对应 +10 mm。若训练范围变成 ±100 mm，同一个 u 对应 +50 mm。

$$
\begin{aligned}
u &= 2\frac{a-l}{h-l}-1,\\
a &= l+\frac{u+1}{2}(h-l).
\end{aligned}
$$

这是教学用仿射映射，不是所有模型的归一化规则。常见规则包括逐通道 z-score、物理边界 min-max、训练分位数映射，以及对夹爪等通道单独处理的 mask。

| 检查 | 为什么需要？ |
|---|---|
| 只用训练集拟合统计量 | 测试分布不能提前参与训练处理 |
| 保存每通道名称、单位和 mask | 同一列索引可能对应不同物理量 |
| 处理常量通道与近零标准差 | 避免除零或放大噪声 |
| 记录超界与裁剪比例 | 裁剪会丢失信息，往返不再严格可逆 |
| 对非饱和样本做往返测试 | 确认统计、顺序和正逆变换一致 |

OpenVLA 的 `unnorm_key` 必须匹配 checkpoint 的数据统计；存在多个数据集统计时不能随意留空。把机器人 A 的输出用于 B，不能只换统计文件：必须先解决动作语义和运动学差异。

## 4. 动作块、执行前缀与时间集成

动作张量 `[B,H,D]` 表示 B 个样本、H 个未来采样位置、D 个通道。H、执行前缀 K 和动作间隔是不同参数，满足 `1 <= K <= H`。每个训练动作窗口必须留在同一 episode 内；尾部不足 H 步时要明确 padding 和损失 mask。

```text
观测t → 推理L → 执行0 → 执行1 → … → 执行K-1 → 新观测
                  └── 其余H-K步丢弃，下一块使用新观测 ──┘
```

这是一种同步串行策略。增大 K 减少重规划次数，也使后续动作依据更旧的观测；K=1 并不保证最高精度，因为延迟和噪声同样影响控制。一个块可能由一次回归，也可能由多步去噪/积分或串行 token 解码生成。

**时间集成**将不同观测下对同一执行时刻的预测对齐后聚合；**异步队列**让推理与执行重叠；**RTC**在新块生成时处理推理延迟与已提交前缀。这些方法不能相互等同。位置与速度、不同坐标系或未对齐时刻的动作不应直接平均。权重偏向新旧预测取决于具体实现，不能笼统断言越新权重一定越大。参见 [ACT](https://arxiv.org/abs/2304.13705)与[实时动作分块](https://www.physicalintelligence.company/research/real_time_chunking)。

各模型的 H、K 和频率应从所用 checkpoint、数据采样率和实际执行循环读取，不能用“SmolVLA 永远 10 步、OpenVLA 永远 5 Hz”这样的表代替配置。[SmolVLA `select_action`](https://github.com/huggingface/lerobot/blob/v0.4.1/src/lerobot/policies/smolvla/modeling_smolvla.py)可能从内部队列返回一步，不等于每次调用都重新生成整块。

## 5. 四种生成方法如何比较？

| 路线 | 训练信号 | 推理路径 | 核查重点 |
|---|---|---|---|
| 确定性回归 | L1、MSE 等 | 连续输出动作块 | L1 对应条件中位数；MSE 对应条件均值 |
| 离散编码 | next-token 交叉熵 | 生成 token 后解码 | 编码往返误差、token 数与词表约束 |
| 扩散 | 按噪声参数化定义的去噪目标 | 按采样器多步生成 | 预测噪声/样本/速度的区别、步数与质量 |
| 流匹配 | 沿给定概率路径拟合速度场 | 从噪声积分到动作 | 路径、时间方向、目标和求解器一致 |

### 离散 token：通道数不等于关节自由度

原始 [OpenVLA](https://arxiv.org/abs/2406.09246) 使用每通道 256-bin 动作编码。7 个动作通道可以是位置3、旋转3和夹爪1，不意味着控制七个关节。均匀中心量化的教学例子中，区间 [-1,1] 分成 256 箱，每箱宽度为 2/256，最大中心量化误差为 1/256；真实 OpenVLA 还要核对分位数归一化、夹爪处理和 token 索引映射。

[FAST](https://arxiv.org/abs/2501.09747)利用动作序列压缩构造 token，不能用“每通道一个 bin token”的数量公式代替它。两条路线都需测量编码误差和实际生成成本。

### 连续动作与 ACT：结构和输出类型分开

[OpenVLA-OFT](https://arxiv.org/abs/2502.19645)研究并行解码、连续动作、动作块等微调设计。ACT 则包含 CVAE 训练结构与时间集成设计，不应在“确定性 MLP 回归”栏里当作同一种算法。论文中的延迟和成功率只能在其配置下引用，不能作为本仓库测量值。

### 流匹配：写清时间方向

下面采用教学约定：t=0 为噪声，t=1 为数据。线性路径和目标为：

$$
\begin{aligned}
x_t &=(1-t)\epsilon+ta,\\
v^*&=a-\epsilon,\\
\mathcal L&=\mathbb E\|v_\theta(x_t,t,c)-v^*\|^2.
\end{aligned}
$$

真实 [π0](https://arxiv.org/abs/2410.24164)或[SmolVLA](https://arxiv.org/abs/2506.01844)实现可能采用相反时间方向；必须同时修改路径、目标与积分符号。不能把不同论文的公式和代码各取一半。ODE 并不自动保证更快、更平滑或成功率更高；速度取决于专家网络、采样步数、硬件和调度。

### 扩散：不是简单地“减去预测噪声”

[Diffusion Policy](https://arxiv.org/abs/2303.04137)和[Octo](https://arxiv.org/abs/2405.12213)通过条件去噪生成动作。更新式由训练噪声计划和推理采样器决定；直接反复执行 `action -= predicted_noise` 不是完整采样算法。

## 6. 解码之后，执行之前

1. **还原：**解码输出、处理有效通道和 padding、应用对应统计的逆变换。
2. **解释：**核对物理单位、绝对/增量、坐标系、旋转和夹爪约定。
3. **转换：**需要时做运动学/坐标变换；仅修改标签字符串没有转换效果。
4. **调度：**检查观测年龄、动作时间戳、执行前缀和过期策略，按动作合同调度。
5. **验证：**串联输入有效性、限位、速率、碰撞和停止检查，记录真实执行响应。

本仓库 `ActionChunk` 提供容器，完整执行链路仍须逐项实现。[历史控制审查 F002/F003](reviews/content-audit-handoff.md)仍有开放项。详见[部署指南](20-vla-deployment-guide.md)。

## 7. 无 GPU 复算与学习验收

```bash
python examples/vla_contract_lab.py --json
```

[源码](../examples/vla_contract_lab.py)使用 NumPy 合成数据，展示同一个 0.5 的两种物理解释、均匀量化误差、episode 尾部 mask、串行时间线，以及正确/交换/空指令的对照。目标 ID 是手工编码，场景只用一个坐标；它没有训练视觉编码器或自然语言模型，结果不是 VLA 基准。

验收：独立解释输出单位；说明无效 padding 为什么不参与 loss；为自己的 checkpoint 填一张动作合同；改变 K 后先预测观测年龄再用[交互](learning-lab-cn.md#vla)核对。
