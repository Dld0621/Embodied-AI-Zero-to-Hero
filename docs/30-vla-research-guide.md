# VLA 研究导读：动作路线、训练信号与最新公开进展

**来源核对：2026-11-15，Asia/Hong_Kong。** 本页按学习问题组织 22 个模型、方法或研究入口。它们属于不同层级，不能混成一张成功率排行榜。基础教学见[第 09 课](learning-core/09-vla-systems.md)，工程选择见[VLA 专项](specializations/vla-zero-to-one-cn.md)。

这次打开了下列原论文摘要、指定方法页、作者仓库与机构研究说明。表中的方法概括用于定位阅读，未复算论文指标、训练模型或复现实物实验。2026 年 11 月新论文按 arXiv 预印本记录；机构发布说明单独标注，不能据此推定同行评审、完整训练数据或权重已经开放。

## 1. 先画五格，再选论文

阅读任意工作，填出：**当前可见输入 → 条件表征 → 动作生成 → 控制接口 → 验证协议**。另外用不同颜色标记只在训练时使用的教师、深度、未来帧和动作标签。模型自己预测的未来与真实未来观测必须分开。

| 你想解决的问题 | 从哪条路线读起 | 应留下的阅读成果 |
| --- | --- | --- |
| 图文预训练怎样接机器人动作？ | RT-2 → OpenVLA | 图文任务与动作任务各自的输入和目标 |
| 能否直接输出连续动作块？ | OpenVLA-OFT → π₀ → SmolVLA | 动作头、训练目标和推理步骤对照 |
| 为什么动作 token 不只是一维分箱？ | FAST → π₀-FAST | 动作块压缩、重建误差与序列长度 |
| 语言知识为何会在动作训练中退化？ | π₀.₅ → Knowledge Insulation | 梯度在哪里传播/停止、辅助目标训练谁 |
| 推理延迟怎样影响执行？ | RTC → VLALagBench | 时间戳、队列、过时动作和任务敏感性 |
| 如何用人类经验支持灵巧手？ | DexSeed → π₀.₇ → GR00T 2 | 人类数据、机器人监督与跨本体接口 |
| 空间与触觉怎样帮助策略？ | SLA → DexForesight → LingBot-Touch | 教师/传感器在训练和部署时是否存在 |

这是一条教学阅读顺序。ACT、Diffusion Policy、视觉 BC 等也应作为对照，不能在没有语言歧义或跨任务需求的任务里预设 VLA 一定更好。[生成式策略基础](learning-core/06-generative-policies.md)。

## 2. 基础模型与动作输出路线

年份表示该条原始论文的首次 arXiv 年份，不表示所有 checkpoint 或代码同日发布。代码用法、相机数量、动作维度和归一化均需读取所选版本。

| 编号 / 工作 | 输入与输出、动作路线 | 重点读什么与边界 | 本次核对的一手来源 |
| --- | --- | --- | --- |
| V01 · RT-2 · 2023 | 图像与指令 → 编码成 token 的机器人动作；联合图文与机器人任务 | 读动作如何进入语言模型词表及共同训练；文本推理能力不能自动等同物理执行成功 | [论文摘要](https://arxiv.org/abs/2307.15818) |
| V02 · OpenVLA · 2024 | 图像与指令 → 离散动作 token；DINOv2/SigLIP 视觉特征与 Llama 2 主干 | 原始 7B 模型与 OFT 后续配方分开；动作语义取决于 checkpoint、数据集与适配器 | [论文摘要](https://arxiv.org/abs/2406.09246) · [作者仓库](https://github.com/openvla/openvla) |
| V03 · Octo · 2024 | 观测历史和语言或目标图像 → 扩散解码动作块 | 读任务/观测 tokenizer、readout 和新本体微调；它是通用机器人策略，不应套成“预训练 LLM 加 MLP” | [论文 III 节](https://arxiv.org/html/2405.12213v2) · [作者项目页](https://octo-models.github.io/) |
| V04 · π₀ · 2024 | 多模态条件 → 连续动作块；预训练 VLM 加流匹配动作模块 | 读动作专家与条件的连接、噪声时间和动作合同；流匹配不自动保证任何平台的延迟 | [论文摘要及版本历史](https://arxiv.org/abs/2410.24164) |
| V05 · OpenVLA-OFT · 2025 | 适配后的观测输入 → 并行连续动作块；L1 回归 | 读并行解码、chunking、连续表示的组合消融；OFT+ 的 FiLM 语言增强也应单独标记 | [论文 IV 节](https://arxiv.org/html/2502.19645v2) · [作者说明](https://openvla-oft.github.io/) |
| V06 · FAST / π₀-FAST · 2025 | 连续动作序列 → 频域压缩 token；自回归策略再解码动作 | FAST 是 tokenizer，π₀-FAST 是使用它的策略；读 DCT、量化和压缩，区分训练效率与控制响应时间 | [论文 V 节](https://arxiv.org/html/2501.09747v1) · [作者实现](https://github.com/Physical-Intelligence/openpi) |
| V07 · SmolVLA · 2025 | 图像、指令与状态 → 流匹配动作专家生成动作块 | 官方发布为约 450M 总参数；异步执行栈和动作生成器分别核查，不把旧示例命令当作当前 API 保证 | [论文摘要](https://arxiv.org/abs/2506.01844) · [官方架构说明](https://huggingface.co/blog/smolvla) |
| V08 · π₀.₅ · 2025 | 多机器人、图文与高层语义共同训练；语言任务与低层动作相连 | 读异构任务与语义子任务；原始论文、后续 KI 配方及 openpi 实现属于不同发布材料 | [原始论文摘要](https://arxiv.org/abs/2504.16054) · [当前 openpi 说明](https://github.com/Physical-Intelligence/openpi) |

截至本次核对，openpi README 明确列出 π₀、π₀-FAST、π₀.₅ 三类模型，并注明公开实现中 π₀.₅ 的训练与推理支持流匹配头。后续研究模型的新闻不能自动变成这个仓库的 checkpoint。[作者仓库模型列表](https://github.com/Physical-Intelligence/openpi)。

## 3. 训练、记忆、执行与通用模型的新进展

这些条目回答不同系统问题。对外发布新模型、公布技术报告、开放推理权重和发布完整训练代码是四种不同事件。

| 编号 / 工作 | 主要接口与贡献 | 怎样检查、公开证据到哪里 | 一手来源 |
| --- | --- | --- | --- |
| V09 · Real-Time Chunking · 2025 | 在执行当前动作块时生成下一块，对必须执行的前缀施加一致性约束 | 是推理时执行方法，不是新 VLM；读冻结前缀与 inpainting，检查延迟和块边界，不能把普通线程直接称为 RTC | [论文摘要](https://arxiv.org/abs/2506.07339) |
| V10 · Knowledge Insulation · 2025 | 阻断动作专家梯度对 VLM 的干扰，同时用离散动作等目标学习控制表征 | “冻结所有主干参数”和“阻断某条梯度路径”不同；读 stop-gradient 与辅助训练目标 | [作者方法说明](https://www.pi.website/research/knowledge_insulation) |
| V11 · π*₀.₆ / RECAP · 2025-11-17 | 结合示范、人工纠正与自主经历，改进 π₀.₆；使用 advantage-conditioned policy 的 RL 路线 | 这是官方研究发布与所链接报告；检查价值信号、纠正与自主数据来源，不把它当作 vanilla BC | [官方研究说明](https://www.pi.website/blog/pistar06) |
| V12 · Multi-scale Embodied Memory · 2026-03-03 | 近期视觉历史与长期语言记忆共同支持多阶段控制 | 历史信息有助部分可观测任务，也可能诱发因果混淆；读记忆更新和任务进度评估 | [官方研究说明](https://www.pi.website/research/memory) |
| V13 · π₀.₇ · 2026-04-16 | 观测、记忆、语言与视觉子目标等条件连接动作专家，强调可控性与组合泛化 | 核对人类语言 coaching、微调高层策略和直接执行分别参与哪些实验；官方演示不能扩展成任意未见任务保证 | [官方发布与所链接论文](https://www.pi.website/blog/pi07) |
| V14 · GR00T N1.6 · 2025-12-15 | Cosmos-2B VLM 变体与更大 DiT，主要本体使用状态相对动作块 | 读相对动作、训练统计与异步执行；相对动作的小数据累计误差仍须检验 | [NVIDIA 研究页及模型卡入口](https://research.nvidia.com/labs/gear/gr00t-n1_6/) |
| V15 · Gemini Robotics 2.5 · 2026-11-10 | 官方 VLA 发布，区分 Gemini Robotics-ER 高层工作流与手臂/手动作模型 | 本次证据为机构发布说明，页面称面向机器人合作伙伴推出；未据此确认可下载权重、完整训练代码或动作头细节 | [DeepMind 官方发布](https://deepmind.google/blog/gemini-robotics-2-5-accelerates-real-world-physical-intelligence/) |
| V16 · GR00T 2 · 2026-11 | 视频历史、指令和机器人状态 → 联合去噪未来视频与动作；属于 WAM 对照 | 比较“预测未来视频”与真实执行视频，核对每本体动作头；本次页面写明代码将于 12 月提供，当前不计作已发布代码 | [NVIDIA 研究页与白皮书入口](https://research.nvidia.com/labs/gear/gr00t-2/) |

GR00T 2 被列入本页是为了比较 VLA 与 WAM 的设计边界：增加未来视频预测改变了学习目标与计算需求，不能仅凭名称认定所有 VLA 都必须有一个世界模型。Gemini Robotics-ER 的空间推理/工具调用接口也不等于可直接输出低层电机动作的公开 VLA 接口。

## 4. 本月预印本：空间、触觉、数据与延迟

下面六篇按**首次 arXiv 提交时间**记录。SLA 与 DexForesight 的辅助空间监督只在训练中使用；BAT-WAM 的特定未来触觉任务需要目标时刻 RGB；这些信息可用性边界影响方法能否用于你的场景。

| 编号 / 预印本 | 被改变的系统位置 | 训练 / 推理要分清什么 | 一手来源与本次核查范围 |
| --- | --- | --- | --- |
| V17 · VLALagBench · 2026-11-02 | 系统评估：任务类型、物体速度、同步/异步执行与推理延迟 | 延迟对成功率的影响随任务与策略改变；其数值不能作为所有任务的通用阈值 | [论文摘要](https://arxiv.org/abs/2611.03103)；未重跑基准 |
| V18 · SLA · 2026-11-05 | 从 π₀.₅ 初始化，持续预训练动作预测及中间视觉表征的空间对齐；自适应层门控与 state dropout | 冻结 3D 教师利用 RGB 及部分可用深度/标定；辅助组件用于训练，保留原推理架构 | [论文摘要](https://arxiv.org/abs/2611.08373) · [方法 §3.2](https://arxiv.org/html/2611.08373v1)；未核查训练复现 |
| V19 · BAT-WAM · 2026-11-07 | 视觉条件连接手状态/动作与触觉流的潜在表征、codebook 与 decoder | 特定未来触觉预测条件包含目标时刻 RGB 和历史动作；它不等于仅凭当前 RGB 预测未知未来的完整触觉 | [论文摘要](https://arxiv.org/abs/2611.10967)；未核查全部实验协议 |
| V20 · DexForesight · 2026-11-08，v2 11-10 | 训练时用动作条件空间世界模型向策略 latent 注入手与场景动态知识 | 教师训练利用离线深度、手运动学和示范；部署只保留 RGB、语言、状态条件策略，无显式未来预测 | [v2 摘要与版本历史](https://arxiv.org/abs/2611.11166v2)；未重算指标 |
| V21 · LingBot-Touch · 2026-11-09 | 把不同物理类型的触觉传感器编码为统一触觉 token，接入不同策略 | 这是触觉基础表征，不是单独的动作策略；必须核对目标传感器、训练映射和接入策略是否匹配 | [论文摘要](https://arxiv.org/abs/2611.12806)；未复现跨传感器实验 |
| V22 · DexSeed · 2026-11-10 | 人手物体交互 → 重定向/扩增 → 物理执行与成功筛选 → VLA 示范 | 手臂跟踪预计算轨迹，RL 手指策略实现动作；成功 rollout 的渲染观测与动作成为训练数据 | [论文摘要](https://arxiv.org/abs/2611.14092)；未重建数据生成管线 |

阅读 SLA 时先问“老师的空间信号从哪里来，学生哪些特征与之对齐”；阅读 DexForesight 时先画“世界模型训练 → 冻结 → 策略表征对齐 → 仅策略部署”。两种训练信号的存在都不代表目标机器人在推理时拥有相同的深度或未来标签。

阅读 DexSeed 时，把姿态恢复误差、重定向误差、接触执行失败、成功筛选和训练集覆盖分别记录。数据生成管线产生更多帧，不直接等于更多独立、可靠的演示。[接触与残差课程](learning-core/08-contact-retargeting.md)。

## 5. 不依赖排行榜的实验选择

先定义你要测的能力，再选资源足够的基线。固定模型选择预算、训练数据、初始状态和评估协议；预训练来源、控制频率、执行前缀、推理成本与人工干预分别报告。不同数据与硬件的论文数字保留原出处，不能直接拼成共同基准。

| 实验问题 | 必须有的对照 | 主要结果 |
| --- | --- | --- |
| 语言是否改变目标？ | 同场景交换指令、空指令、物体位置交换 | 按指令完成率、错物体率、完整任务结果 |
| 空间教师有没有帮助？ | 同骨干/数据/预算，有无对齐；分别控制 depth 与标定可用性 | 空间偏移下结果、接触失败与推理成本 |
| 触觉是否提供额外信息？ | 同任务 RGB+状态，与加入目标触觉表征比较 | 滑移、持物、放置释放与传感器缺失退化 |
| 加速是否值得？ | 原执行与加速版本，同样初始状态与动作合同 | p50/p95 延迟、观测年龄、吞吐、成功与失败 |
| 人类数据是否产生有效迁移？ | 机器人数据基线，加入人类数据/生成数据；固定目标域数据 | 未见物体/场景/任务分组结果及失败模式 |

一次论文阅读的最低产物是一页证据卡：引用与版本、任务、训练输入、部署输入、动作语义、额外标注、基线和未解问题。进一步复现时再加入配置、日志、种子、权重与可回放回合。
