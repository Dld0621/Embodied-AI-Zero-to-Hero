## One closed loop

<div class="dof-loop" aria-label="Embodied intelligence closed loop">
  <div><span>01</span><strong>Observe</strong><small>Sensors, frames, state, uncertainty</small></div>
  <i>→</i>
  <div><span>02</span><strong>Decide</strong><small>Goals, policy, reasoning, prediction</small></div>
  <i>→</i>
  <div><span>03</span><strong>Act</strong><small>Control, limits, watchdogs, stops</small></div>
  <i>→</i>
  <div><span>04</span><strong>Evaluate</strong><small>Task metrics, failures, learning</small></div>
</div>

Every method must eventually connect observation to evaluated action. A plausible command, open-loop loss, or completed script is not task success by itself.

## Evidence before claims

<div class="dof-proof">
  <strong>Execution is not performance. Simulation is not hardware validation.</strong>
  <p>The repository separates import, smoke execution, deterministic tests, benchmark evidence, and bounded hardware validation. A lower level never implies a higher one.</p>
  <p><a href="VALIDATION/">Validation policy →</a> · <a href="CLAIM_REVIEW/">Accuracy gate →</a> · <a href="benchmark_report/">Benchmark report →</a></p>
</div>
