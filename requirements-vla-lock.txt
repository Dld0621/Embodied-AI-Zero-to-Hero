# VLA lock file — pinned versions verified on Python 3.10 + Ubuntu 22.04
# Install: pip install -r requirements-vla-lock.txt
# Updated: 2026-08-05
#
# LeRobot version contract:
# - lerobot==0.1.0 (PyPI) does NOT include SmolVLA — it was added in 0.4.0+
# - lerobot[smolvla]==0.4.1 includes the SmolVLA policy at
#   lerobot.common.policies.smolvla.modeling_smolvla
# - Alternative: git clone + pip install -e ".[smolvla]" (latest source)
# - Do NOT use lerobot>=0.1.0 — it resolves to 0.1.0 which lacks SmolVLA
#
# All pins below are aligned to lerobot[smolvla]==0.4.1's declared dependency
# ranges. lerobot 0.4.1 requires: datasets>=4.0.0, accelerate>=1.7.0,
# transformers>=4.53.0 (via the smolvla->transformers-dep extra),
# torchvision>=0.21.0, wandb>=0.20.0. The earlier 2024-era pins
# (datasets==2.20.0, accelerate==0.31.0, transformers==4.41.2,
# torchvision==0.17.2, wandb==0.17.4) conflicted with those ranges and made
# `pip install` abort during dependency resolution.
#
# bitsandbytes is intentionally OMITTED: it is only required for 8/4-bit GPU
# quantization and has no role in CPU-only CI verification. It also fails to
# run on CPU-only GitHub Actions runners (no CUDA). See commented line below.
#
# torch / torchvision are pinned as a matched pair: torchvision==0.21.0
# requires torch==2.6.0 (exact) in its metadata.
#
# tokenizers==0.22.0 is the highest release that satisfies transformers
# 4.57.6's `tokenizers>=0.22.0,<=0.23.0` (note: 0.23.0 does not exist on PyPI;
# only 0.22.0 and 0.23.1, and 0.23.1 exceeds the upper bound).
#
# timm==1.0.19 stays within transformers 4.57.6's tested timm range
# (!=1.0.18,<=1.0.19) to avoid runtime breakage in the vision backbone path.

torch==2.6.0
torchvision==0.21.0
transformers==4.57.6
datasets==4.1.1
accelerate==1.14.0
einops==0.8.0
timm==1.0.19

peft==0.20.0
# bitsandbytes==0.43.1   # removed — not needed for CPU CI; see note above
wandb==0.21.4
